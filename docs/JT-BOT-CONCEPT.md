# Концепт ИИ-чата JustTalk

Статус: реализация для Android 0.16.2 и сервера подготовлена, проверяется на отдельной базе. Публикация в работающий JT согласуется после проверки.

## Согласовано с Мишей

- Модель Qwen работает на сервере в LM Studio.
- В группах и личных переписках между людьми бот вызывается через `@бот`.
- Контекст: до 20 сообщений текущего чата перед вызовом плюс сообщение с самим вызовом.
- Стиль общения каждый пользователь выбирает для себя в настройках. В общем чате ответ использует настройки того, кто вызвал бота.
- В отдельном разговоре с самим ботом упоминание не требуется.
- Музыкальные функции исключены.

## Дизайн по четырём референсам

Исходный интерактивный макет — `refs.html`, раздел «ИИ-бот».

1. В списке чатов вход в ИИ-чат — круглая кнопка с розовым пиксельным ботом рядом с кнопкой создания чата.
2. На стартовом экране — большой аватар, приветствие, карточки подсказок и поле ввода. Убрать музыкальную карточку и упоминание музыкальных оценок.
3. В разговоре с ботом — шапка с аватаром и состоянием ответа, обычные сообщения пользователя, текстовые ответы и карточки с действиями. Служебные отметки «Учтено сообщений», «Нашёл споты» не показывать по уточнению Миши. Состояние «думает» остаётся.
4. В группе — подсветка `@бот`, ответ отдельной карточкой с аватаром, заголовком «JT бот» и пометкой «ответ для всех». Такой же принцип в личной переписке между двумя людьми.

Надпись Claude в старых макетах не соответствует выбранному подключению. Текст статуса и отображение названия модели согласовать при реализации.

## Подключение при реализации

- Сервер JT проверяет вызов, собирает доступные сообщения текущего чата и передаёт их модели вместе с `server/prompts/JT-BOT.md` и выбранным стилем общения.
- Проверка упоминания и ограничение истории выполняются кодом сервера, а не только инструкцией для модели.
- Ответ возвращается в ту переписку, из которой вызвали бота.
- Инструменты для спотов, сборов и напоминаний требуют отдельной реализации. Визуальные примеры в макете не означают, что эти инструменты подключены.
- Уточнить адрес LM Studio, выбранную модель и интерфейс подключения перед реализацией. Не хранить секреты в этих документах.

## Осталось согласовать

- Чем заменить музыкальную карточку на стартовом экране.
- Порядок подтверждения действий, например публикации сбора и установки напоминания.

Интерфейс и серверная реализация подготовлены. Выпуск и изменения работающего сервера согласуются отдельно.

## Действия бота и живые карточки

Запросы вроде «@бот включи это видео», «@бот скинемся на заказ» и «@бот позови кентов на этот спот сегодня к 19:00» должны приводить к созданию настоящих объектов JT. Текстовое описание не заменяет карточку.

### Авторство

- В созданной ботом карточке показывать аватар и имя «JT бот», а также «По просьбе <имя пользователя>».
- Отдельно сохранять инициатора запроса и признак создания ботом. У обычных карточек сохраняется обычное оформление.
- Права на просмотр и управление определяются участием и правами инициатора в чате. Бот не получает права администратора из-за своего авторства.
- Сообщение и карточка появляются в том чате, откуда пришёл запрос. В отдельном разговоре с ботом адрес назначения нужно выбрать или явно указать.

### Смотреть вместе

- По переданной ссылке или доступному видео создать комнату совместного просмотра и WatchCard.
- В карточке: название, источник, число зрителей и кнопка «Смотреть», с существующим переходом в совместный просмотр.
- Если видео не указано, попросить ссылку или файл. Не выбирать случайное видео.
- Создание комнаты не должно самопроизвольно открывать плеер на устройствах всех участников: они присоединяются кнопкой.

### Скидываемся

- Создать реальную SplitCard: цель, общая сумма, участники, доли, реквизиты при наличии и отметки об оплате.
- Поддержать сценарий из референса: разные доли участников, пересчёт «Поровну» и действие «Напомнить завтра».
- Участников связывать с реальными ID текущего чата. Не подставлять имена из макета и не выдумывать доли при недостатке данных.
- В текущем приложении суммы задаются в целых рублях и должны точно сходиться; проверка выполняется сервером.
- В текущем коде есть создание равных долей через createSplit. Для произвольных долей и напоминаний потребуется расширить инструменты и проверить поддержку сервером.

### Позвать кентов на спот ко времени

- Создать GatherCard, привязанную к настоящему споту: название, дата, время, место и выбранные участники.
- В карточке должны работать «Иду», «Может», «Не иду», показ ответов участников и переход к споту на карте.
- При неоднозначном споте, дате, времени или составе приглашённых уточнить недостающие данные.
- Напоминания и приглашения должны быть настоящими событиями JT; не писать «позвал», пока сервер не подтвердил действие.

### Остальные функции

- Подключать возможности постепенно через явный каталог инструментов сервера: например, опросы, поиск спотов и напоминания.
- Для каждого инструмента определить аргументы, проверку прав, возвращаемую карточку, подтверждение действий и обработку ошибок.
- Кнопки внутри карточек запускают явное действие пользователя. Требование `@бот` относится к запуску по обычным сообщениям, а не к нажатию этих кнопок.
- Наличие карточек в приложении уже проверено в Android-коде: WatchCard, SplitCard, GatherCard и PollCard. Инструменты вызова этих функций моделью пока не подключены.

## Реализованный порядок действий в личном чате бота

- В строке «Карточки в…» пользователь выбирает переписку, куда бот сможет создавать карточки. История из этой переписки при этом не подгружается: контекст остаётся из текущего разговора с ботом.
- Без выбранной переписки бот разговаривает, ищет доступные споты и может поставить напоминание в этом же разговоре, но просит выбрать назначение для групповых карточек.
- После создания в другом чате появляется переход «Открыть чат с карточкой».
- В обычной группе или личной переписке назначение всегда фиксировано текущим чатом.
- Изменение долей доступно инициатору до отметок об оплате другими участниками. Напоминание кнопкой ставится на завтра в 10:00 по Москве.
- История ограничена 20 сообщениями и размером текста на сообщение для модели с контекстом 8192 токена. Если важный текст обрезан, бот должен запросить уточнение.
- После ошибки можно повторить запрос; уже сохранённые действия не выполняются заново.

## Подготовка сервера

- `server/jt_bot.py` использует локальный LM Studio через `/v1/chat/completions`, без облачного провайдера. Проверенный идентификатор модели: `qwen/qwen3.5-9b`.
- Значения по умолчанию соответствуют LM Studio на том же ПК. Необязательные переопределения — `server/bot_config.json` по примеру `bot_config.example.json`; файл с ключом исключён из Git.
- API LM Studio должен быть запущен. Внутренние рассуждения отключаются параметром `reasoning_effort: none`, проверенным на установленной версии LM Studio.
- Перед публикацией скрипт `jt-deploy.sh server` делает резервную копию, переносит серверный модуль и инструкции, затем перезапускает JT. Применять его после согласования выпуска.
- Автотесты сервера: `server/.venv/bin/python -m unittest discover -s server/tests -v`. Они используют отдельную временную базу.
- API и механизм вызова функций сверены с [документацией LM Studio](https://lmstudio.ai/docs/developer/openai-compat/tools).

## Уточнения по проверке Миши

- Поручения вроде «napishi rome kak dela» должны искать адресата и готовить сообщение, а не трактоваться как приветствие боту. Отправка такого сообщения — по кнопке на карточке с точным получателем и текстом.
- Служебные плашки с числом прочитанных сообщений и выполненными поисками скрыты. Проверяемый журнал действий сохраняется на сервере.
