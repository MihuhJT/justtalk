# Промт: фронт мессенджера «Кенты» (этап 1, веб-версия)

Сделай веб-клиент мессенджера для нашей компании друзей («кентов»). Это закрытый мессенджер только для своих: человек 10–20,  без чужих.

## Контекст
- Бэкенд потом будет на FastAPI + WebSocket + PostgreSQL на домашнем мини-ПК. Сейчас его нет, поэтому фронт работает на **моковых данных** через отдельный слой `api/`. Позже я подменю его на реальные запросы, не трогая компоненты.
- Веб-версия идёт первой, чтобы быстро проверить идею. Потом будет Android на Kotlin, поэтому структуру экранов и данных делай простой и переносимой.
- Мой уровень средний: код пиши простой и читаемый, без лишних абстракций. Неочевидные места коротко комментируй (на английском).

## Стек
- Vite + React + TypeScript.
- Стили: обычный CSS с переменными (CSS variables), без Tailwind и UI-китов.
- Состояние: React state + context. Без Redux.
- Роутинг: react-router.
- Шрифты: Unbounded (заголовки), Manrope (текст), JetBrains Mono (время, служебное). Google Fonts.

## Дизайн
Стиль как в нашей карте фич: светлый, чистый, плотный, со скруглениями. Обязательно тёмная тема (по системной настройке плюс переключатель).

```css
/* light */
```

- Пузыри сообщений: радиус 18px, у «своих» срезан правый нижний угол (6px), у чужих левый нижний. Свои справа и синие, чужие слева, белые с рамкой.
- Имя автора и время мелко, моноширинным шрифтом.
- Адаптив: на компе две колонки (список чатов + чат), на телефоне один экран с переходом назад. Ширина от 360px, без горизонтального скролла.

## Экраны и функции (этап 1)
1. **Вход по инвайту.** Экран «Введи код приглашения» + имя + аватар (загрузка картинки или буква по умолчанию). Ссылка вида `/invite/:code` сразу подставляет код. Без кода войти нельзя.
2. **Список чатов.** Личные и групповые вместе. У каждого: аватар, название, последнее сообщение, время, счётчик непрочитанных. Сверху поиск по названию чата.
3. **Чат.**
   - Лента сообщений, группировка подряд идущих от одного автора, разделители по дням.
   - Галочки: отправлено / доставлено / прочитано.
   - Индикатор «Рома печатает…».
   - Реакции эмодзи на сообщение (долгое нажатие или ховер → панель из 6 эмодзи).
   - Ответ на сообщение (цитата сверху).
   - Поле ввода: текст, Enter отправляет, Shift+Enter перенос; кнопка прикрепить фото/видео.
4. **Фото и видео.** Превью перед отправкой, в ленте миниатюра, по клику полноэкранный просмотр.
5. **YouTube в чате.** Если в сообщении ссылка на YouTube, показываем карточку с превью, по клику ролик играет прямо в чате через **официальный встраиваемый плеер YouTube** (iframe). Ничего не скачиваем.
6. **Опрос «куда идём».** Создание из меню «+»: вопрос и варианты. В ленте карточка с голосованием и живыми процентами.
7. **Групповой чат.** Создать группу, выбрать участников, название, аватар. Экран инфо о чате со списком участников.
8. **Профиль и настройки.** Имя, аватар, тема (светлая / тёмная / системная), выход.

### Наши фишки: пока заглушки
- **Карта спотов** (BMX-споты) и **Оценки музыки** (оценка трека 1–10 по критериям) — главные фишки, но делаем их следующим шагом. Сейчас добавь в навигации пункты «Карта» и «Музыка» с экраном-заглушкой «скоро» и заложи в типах сообщений `type: "spot"` и `type: "rating"`, чтобы потом карточки встраивались в ленту так же, как опрос.

### Не делать сейчас
Звонки, голосовые, стикеры, поиск по истории, исчезающие сообщения, шифрование, ИИ-бот.

## Данные и API-слой
Опиши типы в `src/types.ts`: `User`, `Chat` (`dm` | `group`), `Message` (`text` | `media` | `youtube` | `poll` | `spot` | `rating`), `Reaction`, `Poll`, статусы доставки.

Слой `src/api/` с интерфейсом примерно такого вида:
- `login(inviteCode, name, avatar)`, `getMe()`
- `getChats()`, `getMessages(chatId, before?)`, `sendMessage(chatId, payload)`
- `react(messageId, emoji)`, `vote(pollId, optionId)`, `createGroup(...)`
- `subscribe(handler)` — события в реальном времени: новое сообщение, «печатает», прочитано, реакция.

Сейчас реализация моковая: в памяти + `localStorage`, с фейковыми кентами (Рома и ещё 4–5 человек), парой групп и историей переписки. Иногда «кенты» отвечают сами и «печатают», чтобы было видно живой чат. Формат событий сделай таким, чтобы потом он один в один шёл через WebSocket.
